    Подход

    Принципы выросли из конкретных отказов, а не из методологии. Каждый пункт ниже — это то, что пришлось переделать, потому что «и так работало» оказалось неправдой.

    • 01

      «Настроено» ≠ «работает»

      Зеркало, TURN, хранилище, почта — каждая подсистема отдаёт configured и reachable отдельными полями. Потому что однажды хранилище отвечало 502 целый день, а код проверял только, что переменные окружения проставлены.

    • 02

      Долговечность важнее удобства API

      «Отправлено» значит «сохранено». Ответ клиенту ждёт, пока запись действительно легла на диск и в зеркало. Тест растягивает окно до трёх секунд, убивает процесс SIGKILL внутри него и требует, чтобы переписка вернулась целиком.

    • 03

      Честный интерфейс лучше красивого

      Счётчик посетителей не показывает ноль, пока сервер не ответил «нет данных». Плеер не рисует спектрограмму у потока, который не прошёл через аудио-граф. Если система деградировала — на странице висит табличка с командой, которую надо выполнить, а не пустая 500.

    • 04

      Зависимость — это решение

      Один из проектов живёт вообще без npm-пакетов: свой бандлер, свой парсер ID3, свой STUN/TURN-клиент, свой PRNG. Не из любви к аскетизму — а потому что лишняя зависимость в чужом реестре обновляется не в твой день релизов.

    • 05

      Тест, который не может упасть, — не тест

      Один из скриптов проверки админки печатал отчёт и всегда завершался с нулём — он ничего не проверял. Другой держит зеркало на 800 мс, чтобы окно стало фактом, а не гонкой. Третий поднимает настоящий SMTP-сервер, чтобы проверить отправку кода.

    • 06

      Комментарий — это запись о причине

      В коде ~35–40 % строк — комментарии, и почти каждый объясняет не что делает код, а какой отказ породил эту строку. Через год это единственное, что спасёт, когда архитектуру придётся менять.
